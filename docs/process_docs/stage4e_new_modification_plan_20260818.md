# Stage 4e 修正与继续推进方案

## 1. P0：明确在线决策边界

把流程拆为三步：最长尾产生基线候选；屏障特征只做合法候选过滤；在预先规定的 margin 内决定是否评估或切换。删除或改名 `schedule_barrier_safeguarded` 的完整双日程比较，若保留只能标注为离线分析上界，不能注册为在线算法。每次决策只允许读取当前剩余状态和已发生事件。

## 2. P0：修正释放量和屏障特征

实现“完成该候选后立即新增 ready compute”的精确计算：只沿依赖边模拟释放，遇到未完成前驱即停止，不把所有后代总量相加。将 immediate 与 reachable 分成互斥字段，增加重复计数测试。若需要估计更远屏障，明确命名为“可达后代总计算”并禁止称为释放收益。

删除或重新定义 `packing_complementarity`；对包含极大动作验证其恒为零，避免把恒定字段送入评分。扩展 `last_missing_join` 到计划声明的屏障链深度，或将名称限定为 direct-child join。每个 `structural_exact` 字段附上适用范围和不能推出的结论。

## 3. P1：回归测试和可解释日志

增加单候选、两个候选、远距离 join、重复后代、资源极大集合、需要抢占和强制空闲的最小图。测试在线策略不能调用完整未来 schedule；对每次过滤记录候选、原因、margin、是否抢占、评估预算和结果状态。trace validator 继续作为最终裁判。

## 4. P2：实验设计

使用 45 案例开发/留出分离，并加入 Stage 4a R-P/R-S。比较最长尾、原屏障优先、过滤后屏障、margin 修正和离线 safeguard 五种方法，明确后者只作上界。9 个 motif 作为攻击集，不再只报告没有胜利；报告退化样例及其结构原因。多资源数据需按资源集合冲突类型分层。

## 5. 继续条件

只有在真实留出集上过滤策略不增加最坏差距、在线评估开销有明确上限、所有释放量测试通过后，才继续研究屏障链深度或与选择性 rollout 合并。若仍无胜场，可将屏障特征作为解释性指标结项，不再扩展 priority 变体。

## 6. 推荐的实验矩阵

单通道至少比较最长尾、屏障过滤、屏障 margin 修正和选择性评估四种方法；多资源再加入资源兼容过滤。每类数据分别列随机、攻击、真实，且使用同一预算。对每个案例输出首个不同选择的状态、被过滤的原因、后续释放计算、最终 makespan 和额外运行时间，避免只看总胜负。

## 7. 文档和命名迁移

新结果文件使用正式 Stage 4e 名称，旧 `stage4d_barrier` 只在历史来源栏引用。字段中不要把“屏障收益”写成精确值，使用“当前实现估计”或“实际新增 ready compute”。这样可以避免后续把结构计数误读为理论保证。

## 8. 任务拆分

E1 写清每个特征的输入、输出和单位；E2 修复新增释放及共享后代去重；E3 实现 LT 后过滤与 margin；E4 将 offline safeguard 从在线结果中隔离；E5 加入单通道、多资源反例；E6 重跑开发和留出数据。E1、E2 未通过前不调整权重。

## 9. margin 和过滤规则

过滤器只移除能够由当前依赖事实证明不合适的候选，无法证明时保留。margin 应使用当前剩余最长尾差距并处理并列、零分母和部分完成通信。只有候选与 LT 差距在阈值内时才允许屏障信号改选；阈值在开发集冻结，留出集不重调。

抢占时额外检查当前运行通信是否仍 eligible、剩余工作以及屏障候选的实际新增 ready compute。因为模型规定零切换开销，不需要人为添加 cost，但仍要记录切换次数并观察是否出现高频震荡。

## 10. 验收矩阵

| 项目 | 通过条件 |
|---|---|
| 新增释放 | 与手工依赖推进一致且不重复 |
| join 范围 | direct 与远端字段名称准确 |
| 多资源动作 | 合法、包含极大、节点去重 |
| 在线边界 | 不运行完整备选 schedule |
| margin | 阈值外严格保持 LT |
| 真实留出 | 配置冻结且单独报告 |

## 11. 结果解释规则

离线 safeguard 的结果写作“两个完整日程的较优值”，其运行时间必须包含两次调度；在线方法只允许当前状态的有限计算。若屏障方法最终无胜场但能解释 LT 的决策，可作为诊断模块保留。若出现退化，优先保存反例并分析过滤错误，不用新的词典序层级掩盖。

## 12. 预期产物

一份特征定义表、四个最小反例、修正后的在线算法、离线上界独立 runner、分类实验 JSON 和结论文档。结果需报告 makespan、gap、抢占、forced idle、释放计算量估计误差、运行时间和状态。Exact 未完成的案例不得参与“最优”统计。

## 13. 失败与回退处理

过滤后无候选时回到原 LT 合法动作，不能制造主动空闲；特征计算超预算时忽略屏障修正；多资源动作不包含极大时由公共动作生成器拒绝；真实标签缺失时只运行结构基线并在结果中标注。所有回退都不得静默发生。

## 14. 推进节奏

第一轮只修定义并跑最小图；第二轮在历史 45+22 案例上回归，确认没有合法性退化；第三轮才做开发集阈值；第四轮一次性运行冻结真实留出。若第二轮仍频繁退化，停止调阈值，优先分析首个分歧状态。

## 15. 最终报告要求

报告须把在线算法、离线上界、Exact 分开列，给出各自运行次数和信息范围。结论应明确回答屏障信息是独立排序、过滤器还是 rollout 触发器；若只有后两者有效，就删除“独立屏障策略推荐”的表述。
