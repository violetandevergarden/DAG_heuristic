# Stage 4h 局部关键前沿搜索：代码实现与算法探索计划

日期：2026-08-22  
性质：Stage 4g 之后的新增研究计划，不是已完成算法或收益结论。

## 1. 研究动机

Stage 4g 最终保留了 residual Longest Tail（LT）作为正式算法。LT 成本低、行为稳定，但它只根据每个候选通信后方的一条最长剩余路径排序，无法完整表达以下情况：

- 某个通信虽然 tail 略短，却能更早启动一批可与通信重叠的 compute；
- 两个候选在远端共享大部分下游，真正不同的只是到最近汇合点之间的一小段；
- 当前选择会改变下一批 eligible communication、抢占位置或多资源兼容集合；
- 多资源下，局部较优的是一个完整兼容集合，而不是某个单独通信；
- LT 的错误可能需要两个以上通信决策后才显现。

完整 Rollout 可以看到这些影响，但在 1536/2204 节点图上，一次候选后的完整 LT completion 就可能超过预算。Selective trigger 只能减少调用次数，不能降低一次完整 completion 的成本。

本阶段研究“局部关键前沿搜索”：只保留候选动作产生差异的局部剩余子图，模拟到一个结构或预算边界，再用公共残余界和明确的不确定性规则决定是否覆盖 LT。目标是在不回放整个剩余 DAG 的前提下，取得比纯 LT 更好的首动作判断。

本阶段优先平衡两件事：

1. **算法效果**：修复 LT 在竞争、局部释放、汇合和多资源集合选择上的错误；
2. **算法开销**：每次搜索成本由局部节点数、事件数和展开数共同限制，不随整个剩余 DAG 无界增长。

最终允许得到三种结论：形成通过验证的 `integrated_v1` 条件组件；只保留为小中图诊断工具；或证明当前局部定义不足并停止探索。不能为了得到复杂算法而降低证据标准。

## 2. 不可改变的语义和边界

所有代码继续复用公共可抢占模拟器：

- DAG 依赖为 finish-to-start；
- ready compute 自动开始、不可抢占，可并行并与 communication 重叠；
- communication 只在模拟器允许的离散事件处暂停和恢复，保留剩余工作；
- 有 eligible communication 时不得主动 WAIT；
- 单通道任意时刻至多运行一个 communication；
- 固定多资源动作必须非空、资源兼容且 inclusion-maximal；
- 不允许动态路由、迁移、部分获取资源或按比例共享带宽；
- 同刻事件闭包、forced idle、依赖释放和状态转移只由模拟器处理；
- 基础目标仍为单作业 makespan，多作业目标不在本阶段混入。

搜索算法只能从当前合法动作中选择。局部子图是估值视图，不是第二个执行模型；正式动作仍必须交给完整公共模拟器执行和验证。

## 3. 核心问题定义

### 3.1 基础动作和挑战动作

在当前稳定状态 `s`：

- 单通道基础动作 `a_LT` 是 residual LT 选择的通信；
- 固定多资源基础动作 `A_LT` 是 LT 贪心构造的极大兼容集合；
- 挑战动作只从当前完整合法动作中产生；
- 单通道首版固定最多保留一个 challenger，即 width=2；
- 多资源首版最多保留 LT 集合和一个由有限交换得到的完整极大集合。

不把全部 eligible 或全部极大集合默认放入搜索。候选召回和候选估值必须分开报告。

### 3.2 局部差异区域

对两个候选动作分别执行一次公共 simulator step，得到状态 `s_LT` 和 `s_C`。定义局部差异区域时，只考虑两个状态之间可能影响近期调度判断的残余差异：

1. 状态不同的 communication：完成、暂停、剩余工作量或 eligible 状态不同；
2. 因首动作不同而新启动、完成或仍被阻塞的 compute；
3. 从这些差异节点向后可达、直到汇合边界之前的节点；
4. 会在局部窗口内与差异通信竞争同一资源的其他 eligible/suspended communication；
5. 为保证依赖闭包而必须加入的直接前驱；
6. 两个候选完全共享、状态也相同的远端后继只保留边界摘要，不重复展开。

局部差异区域必须由当前 residual state 计算，不能使用原始 DAG 的静态完成假设。

### 3.3 关键前沿

局部搜索在遇到以下任一条件时停止展开，并形成关键前沿：

- 两个候选分支重新达到相同的任务完成/剩余状态；
- 到达首个共同 join 或同步点，并且该点之前的差异已经闭合；
- 到达固定通信决策数 `h`；
- 纳入的局部节点达到 `n_local`；
- simulator expansion、候选数或墙钟预算即将耗尽；
- 后续只剩两个分支完全相同的共享区域。

“到达同一个节点”不等于状态已经汇合。只有影响未来的运行状态、剩余通信工作、活动 compute 和资源相关信息一致时，才允许把后续视为共享部分。

### 3.4 局部评价

每个候选的评价拆成四个字段，不直接形成未经验证的加权总分：

```text
elapsed_local       已推进的真实模拟时间
residual_lower      前沿状态的安全剩余下界
residual_proxy      冻结的低成本剩余估值
uncertainty         代理在开发集校准得到的不确定范围
```

安全剩余下界至少使用：

- residual precedence longest path；
- 单通道剩余通信总工作量；
- 多资源逐资源剩余负载最大值；
- 必须等待的活动 compute 最早完成时间。

`residual_proxy` 首版使用 LT 的局部截断值与共享后缀摘要，不运行完整 completion。barrier、新释放 compute、资源覆盖等只作为独立诊断字段，不在首版中任意加权。

候选只有在评价完整并满足冻结采用规则时才能替换 LT。否则返回 LT。

## 4. 三种采用规则

为了区分理论安全与经验效果，代码和实验必须同时保留三种模式。

### 4.1 严格区间模式

只有 challenger 的悲观界严格优于 LT 的乐观界时采用：

```text
upper(challenger) < lower(LT)
```

这里的 upper 必须是真正可证明的上界；如果只有 proxy，就不能把它命名为上界。预计该模式改变动作较少，但用于检查局部边界能否产生安全证据。

### 4.2 风险受控模式

使用小图 Exact 校准代理误差，形成预先冻结的置信区间。只有预测改善超过：

```text
max(min_absolute_gain, uncertainty_margin)
```

才采用 challenger。该模式允许有限经验风险，但必须报告错误采用率、最坏 makespan 损失和置信度校准，不能声称理论安全。

### 4.3 诊断模式

计算局部估值但始终执行 LT。它用于测量：

- 候选召回；
- 估值排序准确率；
- 局部窗口覆盖首动作差异的比例；
- 每次估值成本；
- 若允许采用，理论上会改变多少动作。

必须先通过诊断模式，再启用风险受控模式。

## 5. 控制算法开销的原则

### 5.1 预注册预算档位

首轮只研究少量离散档位，避免形成大规模参数搜索：

| 档位 | 候选宽度 | 通信决策深度 | 局部节点上限 | 展开上限 | 单决策时间 | 全图附加时间 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| `tiny` | 2 | 2 | 32 | 32 | 2 ms | 0.5 s |
| `small` | 2 | 4 | 64 | 96 | 5 ms | 2 s |
| `medium` | 2 | 8 | 128 | 256 | 20 ms | 10 s |

表中数值是开发初始值，不是结论。只能在开发集选择一个主档位和一个大图安全档位，然后冻结验证。

### 5.2 共享预算

候选生成、局部区域构造、状态复制、simulator step、界计算和缓存共同使用一个预算账户：

- 调用前原子预留；
- 单决策截止时间和整图截止时间同时生效；
- 任一待比较候选不完整时不比较部分结果；
- 达到预算立即回退 LT；
- fallback 后本次决策不调用其他昂贵组件；
- fallback 比例超过冻结阈值后，余下日程切换 `integrated_v0`。

### 5.3 低成本触发顺序

研究顺序必须是“先证明估值有效，再研究选择性触发”。估值未校准前，对开发小图的每个真实 choice 状态运行诊断；估值成立后，才研究以下低成本 gate：

1. eligible 动作至少两个且不等价；
2. LT 与 challenger 的 normalized tail margin 小于冻结阈值；
3. 两个首动作执行后确实产生不同的近期状态；
4. 局部差异区域大小不超过预算；
5. 当前全图预算尚未接近降级阈值。

barrier 不作为硬触发器，只可作为局部差异区域的解释字段做一次有/无消融。

### 5.4 缓存边界

允许缓存静态图结构，如 children、拓扑位置、资源冲突邻接和支配/汇合候选。动态估值缓存键必须保留：

- 每个相关任务的状态和剩余工作；
- 当前活动 compute；
- 当前 eligible/suspended communications；
- 多资源动作所需资源；
- 搜索剩余深度和局部边界版本。

不能只按 task ID、绝对时间或 benchmark 名称缓存。所有缓存优化必须与关闭缓存的结果逐状态对拍。

## 8. 分阶段代码实施

### M0：冻结问题、数据和对照

1. 建立 development、calibration、100--1000 节点冻结验证和 1--2 个成本图清单；
2. 同源、同 seed 和近重复结构不得跨集合；
3. 固定 LT、完整 Rollout 小图上界、周期/随机等成本搜索对照；
4. 固定 `integrated_v0` 为所有不完整评价的 fallback；
5. 为每行保存输入 hash、来源、类别、规模、资源模式和竞争证据。

验收：清单可重复；文件缺失或 hash 不匹配时失败，不自动换图。

### M1：实现局部差异区域

先只实现单通道、两个首动作的差异提取：

1. 用公共 simulator 分别执行首动作；
2. 比较两个 resulting state；
3. 从差异任务向后搜索到最近共同汇合边界；
4. 加入 dependency closure 和窗口内资源竞争通信；
5. 对共享后缀只保留摘要；
6. 达到节点预算时返回显式 truncated，不静默丢节点。

验收：

- 手工 motif 上区域节点与预期一致；
- 候选顺序交换后区域集合对称；
- 零时长 compute 和同刻事件闭包正确；
- 已完成节点不重新计入；
- 共享下游不重复计数；
- 不读取 metadata/reference。

### M2：实现有界前瞻和安全残余界

1. 从候选后的真实状态出发；
2. 每次仍使用公共 simulator step；
3. 深度只计 communication 决策，不计 forced idle；
4. 到前沿或预算边界停止；
5. 计算 elapsed、precedence bound、resource-load bound 和 proxy；
6. 任一候选评价不完整时，正式模式回退 LT；
7. 诊断模式可以保存部分值，但不得据此改动作。

验收：安全 lower bound 在 Exact 可完成小图上从不超过真实最优剩余 makespan；关闭搜索或预算为零时 Trace 与 LT 完全一致。

### M3：小图 Exact 校准

在 Stage 1--3 小图上逐 choice state 比较：

- LT 首动作；
- Exact 最优首动作集合；
- 完整 Rollout 的首动作；
- 局部搜索候选集合；
- 局部估值排序。

分别报告：

- LT 错误状态数；
- challenger recall；
- 区域覆盖率；
- 估值在 recall 成功状态上的排序准确率；
- 错误采用造成的实际 makespan 损失；
- 不同 `h/n_local` 的质量—成本曲线。

候选召回不足时先修正候选/区域，不调估值权重；候选召回足够而排序错误时才研究估值。

### M4：选择主预算和采用规则

只在 development/calibration 集比较：

- `h=2/4/8`；
- `n_local=32/64/128`；
- strict interval 与 risk-controlled；
- 无缓存与结构缓存；
- 全量 choice diagnostic 与低成本 gate；
- 相同预算的 periodic/random 对照。

一次消融只改变一个主要因素。选择一个主配置和一个安全配置后冻结。不得在最终验证集重新选择档位。

### M5：100--1000 节点冻结验证

冻结后运行 random、adversarial、real-derived，分别覆盖 100、300、600、1000 节点以及单通道/固定多资源。至少比较：

- FIFO；
- 固定顺序；
- LT / `integrated_v0`；
- 局部前沿诊断；
- 局部前沿正式候选；
- 等预算 periodic/random；
- 能完成时的小图 Exact；
- 只在小图运行的完整 Rollout 上界。

验证后不得回头调整阈值并沿用同一结果名。修改配置必须形成新版本和新 holdout。

### M6：固定多资源推广

单通道估值通过后再推广：

1. baseline 是 LT greedy maximal set；
2. challenger 是 `remove 1 -> add 2+` 后补全得到的合法极大集合；
3. 局部差异包括资源竞争邻居；
4. 搜索比较完整集合，不能逐通信评价后静默补全；
5. 候选生成与前沿搜索共享预算；
6. 每个候选再次通过 `validate_maximal_action`。

如果多资源候选构造成本已经超过局部估值收益，保留单通道版本，不强行形成统一复杂算法。

### M7：中大图成本与自动降级

只选择 1--2 个预注册的 1500--3000 节点图：

- 每个“图 × 算法”使用独立进程硬墙钟；
- 测量区域构造、前瞻、界计算、公共模拟和 Trace 验证分项时间；
- 报告峰值内存、每触发/每决策成本、fallback 比例；
- 检查超过规模、全图时间或 fallback 阈值后是否一次性降级 LT；
- timeout/error 的 makespan 必须为 null；
- 不从两个成本图推导真实 DAG 总体平均收益。

### M8：准入 `integrated_v1` 或停止

只有所有冻结门槛满足时，才把局部前沿组件加入 `integrated_v1` 并注册。否则：

- 估值有效但成本过高：保留为小中图模式；
- 成本可控但收益不稳定：保留诊断模式；
- 候选召回或估值均失败：记录否定结论并停止该定义。

## 10. 实验指标

### 10.1 效果

- 相对 LT 的 makespan 改善/持平/退化数；
- 总改善、平均/中位数、P95 和最大退化；
- Exact optimal rate、平均/最大 gap；
- 首动作 candidate recall 和 evaluator accuracy；
- 采用次数、正确采用、错误采用和错过改善；
- 抢占数、communication 区间、forced-idle 和资源利用率变化。

### 10.2 开销

- 端到端 wall-clock 和峰值内存；
- 区域构造、候选生成、模拟、界计算和审计分项时间；
- 每次触发的局部节点数、事件数、expansion 和 simulator steps；
- p50/p95/max 单次触发时间；
- 缓存命中和缓存容量；
- fallback 次数、原因和触发后浪费的工作；
- 无收益图上的额外开销；
- 单位额外算法时间对应的 makespan 改善。

### 10.3 局部性是否成立

必须额外报告：

- 差异区域占剩余 DAG 的比例；
- 两候选在预算内真正汇合的比例；
- 未汇合而因预算截断的比例；
- 局部排序与完整 Rollout/Exact 排序的一致率；
- 错误主要来自区域遗漏、候选遗漏、估值还是触发器。

如果局部区域经常接近整个剩余 DAG，本方法没有解决扩展性问题，应停止继续调权重。

## 11. 准入门槛

局部前沿组件进入正式算法必须同时满足：

1. 所有动作和 Trace 合法，公共语义回归全部通过；
2. Exact 小图中 challenger 对 LT 错误首动作有足够召回，目标暂定不低于完整 width=2 Rollout 的 90%；
3. 估值排序相对 LT 有明确净改善，错误采用和最大损失完整报告；
4. 在冻结 100--1000 节点集实际完成非零次评价并改变非零次动作；
5. 冻结集相对 LT 总 makespan 净收益为正；
6. 最大退化不超过开发阶段预注册阈值；
7. 相对等预算 periodic/random 对照仍有正贡献；
8. 1000 节点主配置完整率 100%，没有以 LT makespan 填充 timeout；
9. 1500--3000 节点能在预算内完成或在少量失败尝试前自动降级；
10. 局部区域 p95 明显小于剩余 DAG，额外 wall-clock 与收益相称；
11. 关闭该组件的反向消融会失去对应收益，证明贡献不是其他规则造成；
12. 配置冻结后不依赖 benchmark ID、metadata、reference 或样例身份。

上述 90% 召回只是初始预注册建议；正式实验前可在 development 计划修订中确定一次，但进入冻结验证后不得修改。

## 12. 自动降级条件

出现以下任一情况，当前决策执行 LT；达到整图阈值后余下日程永久切换 `integrated_v0`：

- 没有真正不同的 challenger；
- 局部差异区域为空或超过节点上限；
- 区域依赖闭包不完整；
- 任一候选前瞻未完成；
- 两候选的采用区间重叠；
- operation、event、expansion、memory 或 wall-clock 预算不足；
- lower bound 合同检查失败；
- 缓存 miss 后剩余预算不足；
- 多资源候选不合法或非极大；
- 组件出现可恢复异常；
- 整图额外时间或 fallback 比例达到冻结阈值；
- 输入规模超过验证范围。

fallback 必须记录原因、发生时间和已消耗工作。不能先完成昂贵搜索，再因为超时把结果伪装成普通 LT 完成。

## 13. 停止条件

满足以下任一项，应形成受限或否定结论：

- 局部区域 p95 接近整个剩余 DAG；
- 小图候选召回明显低于完整 Rollout且无法由低成本候选修复；
- 估值在 Exact 状态上的错误损失超过预注册上限；
- 收益只来自开发 motif，冻结集净收益不为正；
- 与相同预算的周期/随机前瞻相比没有独立贡献；
- 100--1000 节点频繁评价不完整，实际长期等价 LT；
- 额外 wall-clock 或内存成本超过 makespan 收益；
- 多资源候选构造吞噬了局部搜索的预算；
- 只有完整后续日程、答案标签或样例身份才能可靠选择；
- 严格区间从不区分候选，风险受控模式又无法限制最坏退化。

停止后仍可保留局部区域工具用于解释 LT 失败，不继续叠加 barrier 权重或更多触发器掩盖估值问题。

## 14. 推荐执行顺序

1. 完成 M0 清单、Exact 首动作口径和等预算基线。
2. 实现 M1 单通道局部差异区域，并用手工 motif 对拍。
3. 实现 M2 安全 lower bound、固定事件前瞻和诊断模式。
4. 在 Stage 1--2 Exact 小图完成 M3：先测候选召回，再测估值排序。
5. 只在召回与估值成立后，用 M4 选择一个冻结预算档位。
6. 完成 M5 的 100--1000 节点冻结验证。
7. 单通道通过后再做 M6 多资源完整集合推广。
8. 对最终候选和安全版本完成 M7 中大图成本检查。
9. 满足全部准入门槛才发布 `integrated_v1`；否则按证据保留诊断或结束。

本计划的首要里程碑不是“让局部搜索改变动作”，而是证明：局部差异区域确实远小于完整剩余 DAG，同时能保留完整 Rollout/Exact 所关心的首动作差异。只有这点成立，后续估值和触发研究才值得继续。
