# Stage 4c：固定多资源 Conflict-Graph Packing 研究

## 1. 阶段定位

本阶段是 Stage 3 的延续，研究固定多资源 DAG 中一次应该同时启动哪些通信。它不研究动态路由，也不把集合选择简化成静态最大独立集问题：候选通信的价值会随 DAG 的剩余依赖、下游计算、join 和 barrier 变化。

## 2. 问题定义

资源集合为 $\mathcal R$。每个通信 $i$ 预先关联非空集合 $R_i\subseteq\mathcal R$。启动或恢复时必须同时获得全部资源；暂停或完成时全部释放。资源集合相交的通信不能并行。

在每个事件点，模拟器给出 eligible communication 集合 $E$。算法选择集合 $A\subseteq E$，满足集合内通信两两资源不相交，且不存在仍与 $A$ 完全兼容的未选通信。后一个条件是 inclusion-maximal，不是选择数量最多，也不是允许主动闲置资源。

以候选通信为顶点、资源集合相交为边得到当前冲突图。合法兼容集合是独立集，work-conserving 动作是极大独立集。研究参数至少包括资源数量、资源集合大小、冲突图密度、热点资源偏斜、多资源通信比例、DP/job 数和同步结构密度。

## 3. 理论探索

先确认退化情形：所有通信使用同一资源时回到单 channel；资源集合互不相交时集合唯一；冲突图为完全图时只需排序。随后研究资源负载、冲突团负载和 DAG longest path 是否可以安全组合。任何下界用于剪枝前必须证明不会高估最优值。不预设一般多资源近似比；静态独立集结论不能直接写成当前事件模型的调度保证。

## 4. 算法探索

### 4.1 简单基线

FIFO 按候选进入 ready 集合的时间排序。Longest Tail 计算候选完成后从其后继开始的剩余最长因果尾部，按尾部降序加入不冲突通信。LRPT 将当前通信剩余工作也计入尾部。所有算法使用相同 tie-break，并在最后检查集合是否极大。

### 4.2 冲突图贪心

每轮为未排除顶点计算 residual tail、完成后新增的 ready 任务、资源热点负载和冲突度等分数。选最高分顶点加入集合，删除其冲突邻居，继续直到不能加入。特征先单独消融，再测试少量有解释的组合，不在测试集逐例调权重。

### 4.3 局部交换与集合前瞻

在初始集合后尝试一次一换一或一换二，新通信必须与集合其余部分兼容，替换后集合仍需极大。只接受统一 Longest Tail completion 得到的严格改善，并限制交换次数。小图可枚举全部极大集合；大图只允许固定候选数和墙钟预算，超时回退基础集合。

## 5. 实验与退出条件

使用 4a 的真实单 job、多 iteration 和 multi-job DAG，按资源热点、图密度、DP/job 数和规模分层，比较 FIFO、Longest Tail packing、冲突图贪心、局部交换和集合前瞻。小图报告 Exact makespan、首个集合是否最优、集合数量和状态数；大图报告 makespan、构造时间、候选/边数量、集合大小、资源利用率、抢占、forced-idle、超时和最坏退化。

必须检查高分大资源通信阻塞多个小通信、低分通信组合覆盖不同关键分支、shared downstream 重复计分、极大集合过早启动和搜索成本超过收益。退出时必须说明何种冲突图和真实 workload 下哪种方法有效、Exact 差距和理论解释；若无稳定净收益，明确停止复杂方法。
