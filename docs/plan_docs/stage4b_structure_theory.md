# Stage 4b：真实 LLM Training DAG 结构理论探索纲领

本阶段研究真实 LLM training DAG 中哪些结构可以帮助调度。所有主要观察必须来自 4a 生成的 SimAI/AICB DAG；合成图只能用于隔离变量和构造反例。阶段结束的标准是得到有证据、有适用范围和有失败条件的结构结论，而不是完成某个分析脚本。

## 1. 研究问题

对每种候选结构回答：它是否稳定出现，是否与通信竞争或最终 makespan 有关，能否转化为调度决策，是否在不同 workload、DP、topology 和规模下仍成立。重点考察：

- micro-batch、iteration 和 pipeline phase 的重复；
- TP、DP、PP、EP 通信的资源占用和先后关系；
- forward/backward、join、optimizer 和同步 barrier；
- 任务完成后释放的计算量和下游通信量；
- 多 job 混合后单 job 结构是否仍可观察。

## 2. 观察方法

### 2.1 结构目录

对每个真实 DAG 建立结构记录：任务角色、阶段、micro-batch、job、依赖层级、资源集合、重复模板和 barrier 关系。统计出现次数、覆盖的 workload 数量和与竞争事件的重合比例。

### 2.2 与调度事件对应

不能只统计静态图。回放 FIFO 和 Longest Tail，记录每个选择点的合法通信、剩余工作、资源冲突、下游释放和最终影响。比较“结构出现”和“策略分歧/完成时间变化”是否同时发生。

### 2.3 重复结构的可利用性

若两个副本看起来相同，逐字段检查外部依赖、当前完成状态、剩余工作、占用资源和同一时刻事件是否相同。只有未来演化确实等价，才能讨论交换或压缩；否则只把它当作描述性特征或缓存索引候选。

## 3. 理论与反例

每条结论使用统一格式：结构定义、成立假设、真实样本证据、可解释的调度影响、反例、适用边界和可能使用的算法。至少构造重复任务跨副本资源冲突、提前完成局部分支但不改变最终 barrier、靠近同步点却不应抢占、以及 multi-job 混合后结构失效的反例。

禁止把“经常出现”写成“必然有益”，也禁止把单一 pipeline schedule 的规律推广到所有训练图。

## 4. 进入后续算法的门槛

结构只有在不同来源 workload 中重复出现，能解释至少一类策略分歧，并且没有明显最坏退化时，才可作为 4c–4g 的特征。若只改善平均值、只在一个 topology 有效或无法区分因果关系，则保留为观察，不进入默认算法。

## 5. 研究产物

- 真实 DAG 结构目录；
- 结构与竞争事件的对应统计；
- 可利用、不可利用和未知结构清单；
- 每条结论的反例和适用边界；
- 指向 packing、rollout、barrier 或 multi-job 的研究假设；
- 对历史结构结论的复核表。

## 6. 退出条件

4b 只有在每个重点结构都完成“真实样本统计 + 调度事件对照 + 反例/边界 + 算法含义”四项记录后退出。最终必须明确哪些结构进入后续研究、哪些被否定、哪些证据不足而暂缓，不能以“发现了重复结构”作为结束理由。
