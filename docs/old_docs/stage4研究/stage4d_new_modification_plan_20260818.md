# Stage 4d 修正与继续推进方案

## 1. P0：先让配置和预算真实生效

统一 depth 语义：0 表示不做后续评估，1 表示只评估下一次选择，2 表示再向前一步；无论配置值如何，结果都写入实际深度。实现真正的 `max_candidates`，候选不足时记录实际数量，候选超过上限时稳定截断并标记截断。

建立可共享的评估预算对象，包含最大完成调用数、最大展开数和软/硬时间限制。每次开始最长尾或挑战者评估前预留成本，超限立即返回明确状态；若底层模拟器不可中断，至少用上限估计拒绝启动，并把“未评估”与“评估后较差”分开。扩展限制必须在每个候选完成前后检查。

## 2. P0：修正触发特征和缓存

将 `heuristic_disagreement` 改为实际运行两个独立的便宜排序器，只有首选不同才为真。`immediate_compute_release`、`last_missing_join` 只依据正在比较的基线与挑战者，不能扫描无关候选。把 `ready_set_delta` 更名为 `eligible_comm_delta`，或者改为真正的 ready task 集合差异，并在文档和 JSON 中保持一致。

缓存键必须包含影响特征的 `previous_eligible`（或其稳定摘要）以及特征版本；增加一个测试：状态相同但前序 eligible 集合不同，缓存结果必须不同。所有特征写明是当前剩余状态量，不得使用原始 DAG 静态总量。

## 3. P1：测试与结果契约

增加 depth=0、候选数 1/2/4、预算恰好用尽、挑战者超限、单次调用超时、缓存前序集合变化、无候选和多个候选的回归测试。结果字段至少包含触发原因、触发次数、每次候选数、实际深度、完成调用、展开数、耗时、回退原因、最终状态和 trace hash。

## 4. P2：冻结开发实验流程

将 45 个案例划分为开发集和冻结留出集，阈值只在开发集选择。随机、攻击、旧真实派生三类分别报告，另加 Stage 4a 的真实 R-P/R-S 小图。每个案例使用多个种子或说明算法确定性；报告 wins、ties、losses、平均/最大差距和调用节省率，不能只报胜场。72-case census 要保存 checkpoint，resume 必须继续已有状态；部分和超时要单列。

先做触发器消融：无条件、只看差距、只看 join、完整触发器；再做阈值 0、0.1、0.25、0.5 的开发集比较。最终留出集只运行冻结配置一次。若调用减少而 makespan 不劣于基线且最坏差距受控，才继续深度二；否则停止增加深度。

## 5. 退出条件

所有配置边界和预算测试通过；独立留出集不出现统计上无法解释的退化；真实派生集至少有可复现的完整案例；结果明确区分最优、可行、部分和超时。满足后可作为选择性评估组件，不满足则只保留为实验脚本，不进入 registry。

## 6. 具体交付清单

代码交付包括预算对象、候选生成器、特征缓存键和结果状态四项变更；测试交付包括深度边界、候选上限、软硬时间限制、缓存隔离和 fallback 五组测试；实验交付包括阈值开发表、冻结配置、独立留出表和超时清单。文档应同时记录旧阈值 0.25 仅为开发值，不能直接作为最终推荐值。

## 7. 风险控制

若评估器无法被安全中断，宁可减少启动次数也不要承诺严格的墙钟上限；若真实数据量不足，先报告“证据不足”，不要用合成案例补齐样本数。任何新增触发信号都必须先有针对性反例和消融实验，再进入默认配置。

## 8. 实施步骤

D1 固化当前 45 例结果和配置为 legacy；D2 修复 depth、候选数和预算契约；D3 修复触发信号与缓存；D4 增加失败模式测试；D5 划分开发/留出并冻结阈值；D6 执行真实派生小图和完整 census。D2、D3 完成前不继续调阈值，因为旧阈值建立在有缺陷的信号上。

## 9. 数据划分原则

同一个模板不同 seed 不应跨开发和留出，以避免结构泄漏。攻击样例单独报告，不参与阈值拟合。真实派生样例按原 workload 分组划分，不能把同一训练配置的相邻切片分到两边。留出集一旦冻结，只在最终配置上运行一次。

## 10. 验收和回退

| 情况 | 应有行为 |
|---|---|
| 不满足触发 | 直接执行 LT，零 completion call |
| 预算为零 | 合法回退，status 标为 skipped |
| 候选评估中超时 | 不选未完成评估者，记录 timeout |
| 所有候选持平 | 使用稳定 tie-break |
| cache key 不同 | 不得错误命中 |
| Exact 未完成 | 不计入 optimal rate |

最终报告除 7/38/0 式胜负外，还要给平均/最大 gap、额外时间、调用分布和 fallback 比例。若阈值 0.25 在留出集退化，应报告失败，不在留出结果后重新调值。

## 11. 结果文件和恢复机制

每个决策记录状态摘要、触发特征、候选、预算前后值和最终动作。长图每隔固定决策数写 checkpoint，内容包含模拟器 runtime、算法缓存版本和随机状态；resume 校验 benchmark hash 后继续，不允许静默从头开始。旧的 partial 文件若缺少这些状态，只能重新运行并标为 legacy restart。

## 12. 与其他阶段的边界

Stage 4d 可以调用 Stage 4c 产生的合法动作作为多资源候选，也可以使用 Stage 4e 屏障特征作为触发输入，但不能接管它们的资源合法性或依赖推进。Stage 4f 的多 job 目标需要独立评估函数，不能直接复用单 job makespan rollout 后宣称改善 JCT。

## 13. 最终决策文档应回答的问题

需要回答哪些状态触发、为什么触发、平均节省多少调用、最坏增加多少时间、在哪类图失败、真实留出是否复现，以及关闭组件后系统如何回退。只有这些问题都有机器可读证据，才可把选择性 rollout 称为正式算法组件。
