# Stage 4b：LT 失败机制与辅助候选诊断计划

日期：2026-09-06  
状态：待执行；对应后续大纲 M1。先阅读 [公共测试协议](stage4_lt_followup_test_protocol_20260906.md) 和 [4b 分纲](../plan_docs/stage4b_structure_theory.md)。

## 1. 要回答的问题

哪些 LT 选择可以通过“只换当前一个完整动作，之后继续 LT”改善 makespan？如果只能依靠长期 job 服务顺序取得收益，一步 LT 辅助可能无效，应明确记录。

区分三层证据：其他策略最终胜过 LT；同一状态存在条件 Q_LT 更小的动作；辅助触发器能在未知输入上识别该状态。前一层不自动推出后一层。

## 2. 输入与状态采集

使用正式 4f 9 图作设计/复现池，并加入既有 Exact 显示 LT 正确的小图和单 job 对照。按公共协议冻结来源和状态版本。

分别回放 LT、FIFO、固定 job 顺序、shortest remaining job 和 job-aware LT。保存 LT 轨迹中的所有决策摘要；离线标签首轮每图每模式最多 32 个状态：按决策 index 均匀取 16 个，再按预先固定风险排序取 16 个，重复去除。风险排序为存在可靠未来释放、LT 前两名相近、多资源替代集合；不得按已知收益筛选。

首次策略分歧可从共同前缀直接比较；轨迹已分叉后，必须克隆同一个完整状态再执行不同动作，不把两条轨迹上的 tail 或最终剩余时间直接当首动作标签。保留 active 通信、remaining compute、job arrival 和策略历史。

## 3. 特征定义与假设

| 特征 | 运行时定义 | 待验证假设 |
|---|---|---|
| tail 相对差距 | (T1-T2)/max(T1,1个时间单位) | 前两名接近时 LT 更容易被小幅修正 |
| 执行时长差异 | max(d1,d2)/max(min(d1,d2),1个时间单位) | tail 接近但 duration 不同时释放时机有差异 |
| 可靠未来释放 | 通信其余前驱完成，仅剩 active compute 的确定完成事件 | 长通信启动可能挡住即将就绪的关键通信 |
| 资源脚印 | 固定资源集合及与替代候选的交集 | 单个 LT 通信可能阻挡多个互相兼容的候选 |
| 最后缺失前驱 | join 的未完成直接前驱集合恰为该通信 | 某候选可马上解除同步等待 |
| job 剩余量 | 当前未完成工作量，running 用 remaining | 跨 job 排序可能解释长期策略差异 |

job 剩余量不是单 job 完成时间估计的精确值。tail、barrier 与 job 信息均来自允许的 DAG/state；source metadata 仅用于离线分组，不进入策略。先量化单特征，避免一开始拟合混合评分。

## 4. 条件标签探索

每个采样状态先选 LT 默认动作，再选至多 3 个不同挑战：LT 第二名、符合条件的 WAIT、多资源局部替换或 barrier 候选。动作不足不强行制造分歧。

离线诊断预算单独设为每状态 30 秒、最多 4 次完整补全、每来源图每模式最多 32 状态；它不进入在线 90 秒质量表。截断记 unknown。先用统一 LT 后续；另对相同动作集合用冻结 job-aware 后续做小规模敏感性分析，完整报告排序一致与不一致。

标签分为 exact_optimal、conditional_improvement、conditional_tie、conditional_worse、unknown，禁止把“动作不同”写成质量正标签。基线值必须完整才能标记改善。按特征报告覆盖、命中、漏检和成本；采样结果只代表指定范围，不能推成全图频率。

## 5. 支持例和反例

每个拟准入特征至少提供一个可手算或 Exact 核对的支持例和反例：
- tail 接近却 LT 正确；tail 差很大却另一个动作更好。
- 等待释放关键通信有利；未来短 tail 通信不值得等待。
- 两个兼容通信并发有利；优先它们反而阻挡更长关键计算。
- 提前 barrier 改善 makespan；barrier 提前但另一条链仍主导。
- 一步动作无差异，但完整 job 策略有差异。

先保留完整前驱闭包构建真实切片。若切片改变 LT 顺序、下一真实事件、候选集合或 Q 排序，记录失真，不用于解释原状态。手工反例必须标 synthetic，不能替代真实结构结论。

交付 state_manifest.jsonl、feature_labels.jsonl、support_counterexamples.md、feature_costs.json 和 admission.md，记录每条假设交给 4c/4d/4e 的理由。
