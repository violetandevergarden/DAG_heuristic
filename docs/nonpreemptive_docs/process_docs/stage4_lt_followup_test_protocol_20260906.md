## 2. 必须先冻结的 LT 定义

复用 src/llm_structured/nonpreemptive/runtime/ 下的 policies、features、completion、adapters 和 replay；现有 selective_rollout/baseline.py 已指向共享基线。执行前审查实际实现并记录版本，不另写时间推进。

冻结以下内容：tail 是否包含本节点时长、running 节点剩余量、资源冲突的合法候选筛选、并列顺序、自动 compute、arrival 表达、optional-idle 的既有 WAIT 规则和多资源集合补全规则。用旧基线逐动作对拍；若需修错，先记录原因并重跑受影响参考结果。

区分：
- LT-original：该模式下现有冻结 LT，包括它已有的 WAIT 规则。
- LT-start：仅在 WAIT 机制消融中使用，存在合法启动时按 LT 立即启动；这是独立策略，不改名冒充 LT-original。
- LT-assisted：默认调用 LT-original，只有规定的检查通过才改当前动作；未触发、预算不足、评估未知、打平均回到原动作。

全体补全实验统一使用同一个冻结 LT-original。替换后续策略仅作独立消融，需单列版本及全部比较结果。

## 3. 数据冻结与防止验证泄漏

建立 manifest，字段至少包括 benchmark_id、content_hash、source_workload_hashes、topology_hash、mode、job_count、完整图/切片、角色、审计范围、已有标签来源、split 和 design_exposure。

将共有父 workload 的组合图视作关联图的连通分量分组，避免 A+B 和 B+C 跨集合。arrival 变体、相邻切片及拓扑变体不得绕过来源隔离。拓扑泛化另设留出检验。

先纳入 9 个正式 4f 图作复现和设计证据，按实际旧使用历史标记；已阅读其失败状态或用于选择算法的旧 holdout 不再承担新的盲测职责。纳入既有 LT 正确、无差异和无竞争控制，不能只挑 LT 输的图。

最终推广结论要求至少 3 个未参与设计的独立来源组；这是本轮最低研究门槛，不代表统计充分。无法取得时仍完成现有输入研究，结论限于已测来源。新增输入按模型/拓扑/规模缺口选择，在查看辅助算法结果前冻结，不按胜负筛选。超大图只作成本诊断；转换不支持的配置保持 unknown/not_supported。

## 4. 公共预算和选择规则

首轮拟定参数如下，开发试跑后最多修订一次，写新配置版本及原因；最终验证前冻结，不能事后移动成功门槛。

| 项目 | 初始设置 |
|---|---|
| 每实例在线调度硬预算 | 90 秒，包含加载后特征初始化、候选、搜索和实际回放 |
| 搜索累计预算 | 20 秒，到限禁用后续搜索；不保证剩余回放必然完成 |
| 每决策搜索上限 | 1 秒；成本曲线单列 0.25/2 秒 |
| 每实例补全调用上限 | 64，基线补全与挑战补全都计数 |
| 每实例搜索状态上限 | 10000；另外统计每次补全的事件和总耗时 |
| 缓存上限 | 256 个完成评估结果；禁止存入截断值 |
| 峰值进程内存上限 | 2 GiB；相同边界监控所有策略 |
| 首轮候选数/深度 | 至多 2 个不同首动作，深度 1 |
| 随机控制 seeds | 0、1、2、3、4 |
| 正式计时 | 1 次预热、3 次测量；预热不用于调参，测量超时全部保留 |

加载、独立 trace 验证、端到端时间另列。补全内部必须检查同一个单调时钟截止时间，不能仅在调用前检查；外层进程硬停止作为最终保障。无硬预算支持时，先补预算基础设施再跑正式实验。

在同一状态 s 上计算 Q_LT(s,a)：执行首动作 a 后由冻结 LT 补全得到最终 makespan。只比较均完整完成且合法的数值。截断值、下界、部分进度不能当成完整 Q。baseline 评估先执行；baseline 未完成时直接回退，避免基线/挑战受到不同未知值待遇。

主配置只接受严格改善，数值容差复用项目时间精度规范并显式记录。挑战超时则保留已确认的默认动作。每次重新计算剩余预算。缓存 key 必须包括 benchmark、完整状态、模式、目标、动作、后续策略和版本；涉及有记忆的策略时还需包含其策略状态。

## 5. 测试层次和统计口径

T0：手算语义测试，包括同刻完成原子处理、compute 自动运行、通信连续性、合法 WAIT、active reservation、零时长和无未来事件；公共语义/转换/Exact 改动需完整测试。

T1：小图 Exact。单 channel、固定多资源、两种模式分别给出 optimal 或 unknown。真实切片保留边界依赖、release 和资源预约；无法保真则只作机制图。候选受限搜索不能宣称枚举全部合法动作。

T2：冻结真实输入基线与消融，执行最终 trace 独立验证，保存超时和失败。固定/随机/攻击/真实分表，单/多资源和两种模式分表。

T3：独立来源验证及成本曲线。参数仅在开发/validation 选择；最终结果揭晓后再改算法，必须重新建立独立验证。

逐图改善率定义为 (C_LT - C_alg) / C_LT；负数表示退化。统计平均值、中位数、最坏退化、完整率、调用率、修复/破坏次数、时间、内存、WAIT/forced idle 及资源利用率。来源组先等权汇总，再作组间平均，避免 arrival 变体放大某来源权重。超时不能用忽略缺失的均值制造优势；报告配对完整子集及全部实例完成率。

初始继续门槛：所有完成 schedule trace 合法；独立验证无新增超时；makespan 来源组平均改善至少 1%，至少两个来源组严格改善，逐图最坏退化不超过 1%；相对 LT 中位调度时间倍率不超过 3。还需与开发阶段冻结的简单强基线逐项比较：若只胜 LT，不胜强基线，则仅支持“LT 辅助修复”，不支持复杂方法值得部署。阈值是工程筛选约定，不是理论保证或显著性检验。
